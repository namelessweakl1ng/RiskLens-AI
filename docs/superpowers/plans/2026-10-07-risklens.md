# RiskLens AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Replace disconnected prototype paths with one explainable financial document analysis system and an honest reproducible ML pipeline.
**Architecture:** One taxonomy and Pydantic contract connect extraction, rules/model inference, scoring, SQLite and vanilla dashboard. Training consumes the same taxonomy. Optional models never prevent rule-only operation.
**Tech Stack:** Python, FastAPI, SQLite, PyMuPDF, Transformers/PyTorch, pytest, scikit-learn, matplotlib, vanilla JavaScript/CSS/SVG.
**Spec:** docs/superpowers/specs/2026-10-07-risklens-design.md and the user's complete uploaded 36-section brief.

## Global Constraints
- All rectangular UI border radii are 0; no frontend framework migration.
- Stable ten-label taxonomy; no fabricated ML confidence, source provenance or metrics.
- Model absence is explicitly rule_only; sentiment never affects risk scoring.
- Keep existing history and PDF workflow, migrate legacy database safely.
- Preserve third-party data until reproducible replacements have been verified.
- No model weights/checkpoints in Git. No paid LLM API.
- User approved design and authorized execution and PR creation without further approval prompts.

## Review Focus
- Negation whose scope crosses punctuation must not produce false risk evidence (Task 1).
- Wrong ten-label model head/order or missing deployment metadata must be rejected (Task 1).
- Legacy databases must not be overwritten or historical fake confidence relabeled genuine (Task 2).
- Near-duplicate chains across document groups must remain in a single split (Task 3).
- Unsafe filenames/HTML and stale model metadata must not corrupt dashboard rendering (Tasks 2/4).
